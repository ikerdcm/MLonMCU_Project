Notes
  • MAX has two models — check the version. v0 (fp32-cpu) IS the shared DS-CNN-L — a hand-coded float32 port (ds_cnn_inference.c: CONV0 → depthwise groups=64 + pointwise 1×1 ×6 → AvgPool → Dense, 3.94 M MACs) on the Cortex-M4, no accelerator (hence 2048 ms). v1 (int8-accel) is a DIFFERENT network — the CNN accelerator can't run the depthwise-separable graph, so it deploys kws12mfcc: 6× standard conv1d (1.34 M MACs), keeping the DS-CNN's own MFCC front-end (10×49) and 12 keywords but no depthwise. NB: this is not the ai85kws20net model — that's a separate, bigger net (kws20_v3: 9 layers, 8.4 M MACs, 128×128 input, 21 classes) in the other folder, unrelated to the DS-CNN branch. So the same-model cross-board comparison is the v0 (fp32) row (Coral = U5 = MAX-v0); the 0.16 ms accelerator number is "best KWS this HW can do".
  • Coral v1 calibration before/after — original deploy used random INT8 calibration → 23.6% (host artifact, works on-device); recalibrated on real MFCC → 92.0%. Kept both for the comparison.
  • Bit-width axis is cross-MCU — 32-bit: Coral/U5 CPU · 8-bit: Coral Edge-TPU + U5 CMSIS-NN + MAX accel · 4-bit: only MAX78000 (ai8x) and GAP9 (NE16) can do it natively; U5 and Coral top out at int8.
  • Coral key finding — Edge-TPU latency is block-count-bound, not filter-bound (every 4-block ≈ 1.8 ms, every 6-block ≈ 2.27 ms) → prune = drop blocks, keep filters. Winner = f64b4 distilled, 1.88 ms @ 90.8%.
  • GAP9 — to be added this week; NE16 accelerator supports int8 and sub-8-bit, so it can also carry the 4-bit story alongside MAX78000.
